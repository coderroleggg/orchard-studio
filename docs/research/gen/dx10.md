# DX10 (FL: Fruity DX10)

FL's Fruity DX10 is Image-Line's port (Frederic Vanmol, interface Didier
Dambrin) of Paul Kellett's open-source mda DX10 FM synthesizer, extended with a
second modulator ("Mod 2 ...") and an octave wheel ("Coarse"). Category Synth
classic, `notes: 'voices'`, INS tab (`ins: true`), DefPoly 16.

Sources: FL 2026's plugin binary (`Plugins/Fruity/Generators/Fruity DX10/Fruity
DX10_x64.dylib`, arm64 slice, FPC, class `TTestPlug`, VMT 0x209cb0; no symbols),
its editor form, the 59 factory presets, the plugin-database state, the editor
thumbnail (`Data/Patches/Plugin database/Generators/Synth classic/Fruity
DX10.png`, read-only, for layout and colours) and renders of FL's real plugin
through the scratchpad test host (`flfxhost`). Our engine is FL's code in FL's
single precision and matches FL's output sample for sample (see Fidelity).

The `%7.xf` texts are FPC Format strings, right-aligned in 7 columns, rounded
half to even like printf. FL also lists parameters 22..113 (the INS-tab
envelopes, LFOs and filter, pushed by FL through dispatcher id 90): in Orchard
they are the channel's INS settings.

**Fresh instance.** The constructor (0x5d3xx) sets mda DX10's program 0 ("Bright
E.Piano") with Mod 2 off; `Plugin presets/.../Default.fst` and the plugin
database's `Fruity DX10.fst` (the state FL loads when the plugin is added from
the database or the channel rack menu) hold exactly the same 22 values. So a new
DX10 plays that patch (`def.state()`), while each parameter's `def` keeps the
form's reset value: resetting Mod 1 Coarse gives 55706, resetting a Mod 2 wheel
turns the second modulator on, as in FL.

**Presets**: 59 `.fst` files (event 213 = version 1 + the 22 values; identical to
what the plugin reports after loading them with `flfxhost info --preset`), in
`def.presets`, case-insensitive name order. No channel presets reference DX10.

## DSP (exact, FL's float32; `f()` = round to float32)

Wheels `p_i` are float32 fractions; `ifs = f(1/sr)`, `k = f(44100/sr)`.

Update (on every parameter change), double arithmetic unless noted:
```
tune  = f(8.175798915644 * ifs * 2^(floor(6.9 * p21) - 2))       Coarse -3..3 -> 2^-2..2^4
ratio = f(2^30 * f(floor(40.1 c^2) + fine(f)))                    c = p3, f = p4 (Mod 2: p14, p15)
fine(f) = f < 0.5 ? f(0.2 f^2) : {4: 1/4, 5: 1/3, 6: 1/2, 7: 2/3, else 3/4}[roundEven(8.9 f)]
depth = f(0.0002 k p5^2), dept2 = f(0.0002 k p7^2), velsens = p9   (Mod 2: p16, p18, p20)
vibrato = f(0.001 p10^2)
catt = f(1 - exp(-ifs exp(f(8 - f(8 p0)))))
cdec = p1 > 0.98 ? 1 : f(exp(-ifs exp(f(5 - f(8 p1)))))
crel = f(exp(-ifs exp(f(5 - f(5 p2)))))
mdec = f(1 - exp(-ifs exp(f(6 - f(7 p6))))), mrel = f(1 - exp(-ifs exp(f(5 - f(8 p8)))))   (Mod 2: p17, p19)
rich = f(0.5 - f(f(3 p11) p11)), modmix = f(f(0.25 p12) p12)
dlfo = f(628.3 ifs 25 p13^2)
```
FL scales the modulation depths by 44100 / sr (mda does not), uses round where
mda truncates the fine ratio, and adds Mod 2 and the octave wheel.

TriggerVoice, from FinalLevels.Pitch `P` (cents, 0 at the root key) and
InitLevels.Vol:
```
r = roundEven(P); frac = f((r % 100) * 0.01f)
note = clamp(trunc(f(f(f(P * 0.01f) - frac) + 60)), 0, 127); n = f(note + frac)
vel = clamp(roundEven(f(f(ln(f(min(f(vol*10), 20.551182) + 1)) / ln(21.551182)) * 127)), 0, 1270)   (= MIDI velocity)
l = f(exp(0.05776226505 n)); dcar = f(tune l); l = min(l, 50)
per modulator: L = f(l f(64 + f(velsens f(vel - 64)))); menv = f(depth L); mlev = f(dept2 L)
               inc = low32(roundEven(f(ratio dcar))); phase = 0
env = f(f(1.5 - p11) 0.0035 f(vel + 10)); norm = f(1.2 / env); cenv = 0
```
Per sample (Voice_Render):
```
every 101 samples per voice (counter starts at 0): lfo0 += dlfo lfo1; lfo1 -= dlfo lfo0; mw = lfo1 vibrato
cenv += catt (env - cenv); env *= cdec
x1 = sine[phase1 >> 18]                        FL's host sine table, 16384 points
car = (car + (dcar + mw)) + menv1 x1 + menv2 sine[phase2 >> 18]; wrap car to [-1, 1] by +-2
menv += mdec (mlev - menv) (both); phase += inc (uint32, both)
out = f(norm cenv) * (modmix x1 + car + car^3 (rich (car^2 - 1) - 1))     both channels
after the block: env < 0.0002 -> finished (cdec = 1); menv < 2^-24 -> menv = mlev = 0
```
The carrier phase runs over [-1, 1] (period 2), so key 60 plays **261.63 Hz**,
an octave below FL's other instruments (C5 = 523.25 Hz), with each Coarse step an
octave (measured: 32.70 Hz at -3, 2093 Hz at +3). The modulators are integer
phase accumulators (`2^30 ratio dcar` per sample over 2^32), i.e. at
(coarse + fine)/2 times the carrier. The output is normalised by the initial
envelope (`1.2 / env`): velocity does not change the DX10 level itself (only
FinalLevels.Vol does), it sets the modulation depth through VEL.SENS, and low
velocities end sooner (absolute 0.0002 threshold). FL's single LFO is stepped by
every voice from its own counter, so it runs faster with several voices.

A FinalLevels.Pitch change (pitch knob, bends, slides) recomputes dcar and the
modulator increments with the current tune and ratios (`l` is not clamped
again; the envelopes and the depths keep their trigger values), checked once
per render call. Running voices read rich, modmix, vibrato and dlfo live; a
release takes the current crel / mrel; attack, decay and the depths are copied
at the trigger.

Voice_Release: `cdec = crel; env = cenv; catt = 1; mlev = 0; mdec = mrel` (both
modulators). The voice finishes when env < 0.0002 after one of its blocks and FL
kills it right after that block (no declick).

FPE_MaxPoly (0x5e760): with max polyphony N (FL sends the channel's), once N
unfinished voices play TriggerVoice first silences the quietest of them (env = 0;
the first of equals in FL's voice list, a TList whose Delete moves the last item
into the gap) and FL kills it after its next block.

Dispatcher (0x5cce0): FPD_Flush flags every voice finished (killed after its next
block); FPD_SetSampleRate re-runs the update; FPD_UseVoiceLevels answers 1;
FPD_ShowSettings (the wrapper's settings button) swaps the editor for the
plugin's INS settings sheet (Orchard: the channel settings' INS tab).

**FL's sampler processing** (inside the plugin; FL pushes the channel's INS
settings into it). With the INS envelopes, LFOs and filter off (FL's defaults)
it only applies the voice levels: `L = f(cosf(a) vol)`, `R = f(sinf(a) vol)` with
`a = f(f(pan + 1) pi/4)` (pan clamped to -1..1) from FinalLevels; the first block
starts at these gains, later blocks ramp from the previous gains with
`step = f(f(target - last) / len)` clamped to +-0.001 per sample (fixed, at any
sample rate; the target moves to `last + step len` when clamped), mixed by FL's
NEON kernel: gains in float32 for frame pairs stepped by `2 step` in groups of
8 frames, and for the remaining frames of a block the left gain takes the right
step and vice versa (a quirk of the kernel). Then Gen_Render kills the finished
voices (host Voice_Kill).

## Our implementation

- `src/model/gen/plugins/dx10.ts`: parameters, value texts, presets, fresh state,
  `levels: 'plugin'`, view state (`keyboard`, `kbView`).
- `src/engine/gen/plugins/dx10.ts`: the port above (update, TriggerVoice with
  the voice stealing and FL's voice list, pitch update, Voice_Render with its
  end-of-block checks, Voice_Release) in float32 (`Math.fround`), FL's host sine
  table, and FL's level stage per render call (pan law, ramp step and the NEON
  kernel with its remainder quirk). The end-of-block checks run once per channel
  render call (FL's block); the level ramp runs per control step (<= 16 samples,
  where the channel updates the levels). `setMaxPoly(n)` = FL's FPE_MaxPoly
  (default 16). 128 preallocated voices; `monitor()` reports the held keys for the
  editor keyboard. Only departures: non-finite parameters, pitch and levels are
  ignored / zeroed and a NaN carrier phase is reset (FL would loop forever).
- `src/ui/plugins/gen/dx10/`: the editor (see below).

## Fidelity (FL 2026 host renders vs ours through GenChannel, 44.1 kHz unless noted)

DX10's output depends on FL's processing blocks in three places: a finished
voice is killed after the block in which its envelope fell below 0.0002 (FL
renders the rest of that block), modulator envelopes are cleared below 2^-24
after a block, and the single vibrato LFO is advanced by each voice within a
block, voice after voice. Our voice treats each channel render call as FL's block
(a step that starts at a lower frame than the previous one begins a new block).

- **With FL's block structure** (the test host's: at most 512 samples from each
  split, split at note on / off, parameter changes and ticks; reproduced by
  rendering the channel in the same calls): **bit-exact, every sample**, for the
  default patch, three-voice polyphony, two-voice vibrato, the Effect preset
  with three voices, all 59 factory presets with two overlapping notes each
  (2.5 s, including the voice ends and the release tails), parameter changes
  during a note, 48 kHz, and 128-sample blocks at 97 BPM.
- **In the engine's 128-sample blocks** (normal use): bit-exact until each
  voice's end for single notes of the default patch at keys 0, 36, 60, 84, 127,
  velocities 1, 64, 100, 127, note pan and fine pitch, Coarse -3 / +3, Mod 2, Mod
  Thru, Waveform 0, attack, held decay, vibrato, at 22.05 / 48 / 88.2 / 96 kHz,
  parameter changes (Waveform, Mod Thru, Attack / Decay, Mod Coarse / Coarse), a
  channel pitch change, and polyphony without vibrato. The voice ends at the end
  of its 128-sample block instead of FL's block (its last samples are at about
  -66 dB re its peak: max abs error 1.3e-4..3.6e-4, overall -87..-98 dB; a
  velocity-1 note -69 dB). 50 of the 59
  presets play a note bit-exactly until its end; the other 9 (modulator sustain 0)
  differ by at most 3.1e-6 (-100 dB re peak) before it (the 2^-24 clearing at
  another block end). Polyphonic vibrato differs in phase when the blocks differ
  (-17 dB in a strong two-voice case).
- **Level changes**: FL ramps the voice gains per block; we ramp per control
  step (FinalLevels change per step here), so after a channel volume / pan change
  the gains differ within the ramp (up to 0.025 for 100 % -> 50 %, about 640
  samples) and are equal again after it.
- **Levels at some velocities / volumes**: FL computes InitLevels.Vol and the
  channel volume with float32 LogVol; Orchard's shared levels use doubles, so
  some values (velocity 60, 90 or 128, channel volume 50 %) are 1 float ulp apart
  (6e-8 relative). Velocity 100 at channel volume 100 % is exact.
- **Voice stealing** (FPE_MaxPoly, with FL's block structure): the same voices
  are stolen (FL's voice list order, its unordered delete included) and the
  output is exact once the stolen voice has gone; when the stolen voice renders
  before the new one in the channel's order, its fade starts one block late
  (FL calls TriggerVoice before the block). FL sends the channel's max
  polyphony (DefPoly 16 when the plugin is loaded, FLEngine 0x384b94 -> 0x756190,
  and on every change); Orchard's channel sends it the same way (`setMaxPoly`,
  GenChannel).

## Editor

FL's layout at the form's coordinates (panel + control Left / Top): MISC (WAVE,
COARSE, LFO RATE, VIB), AMPLITUDE (envelope display, ATT, DEC, REL), MODULATION 1
(COARSE, FINE, VEL.SENS, THRU, display, INIT, TIME, SUS, REL), MODULATION 2 (no
THRU), the logo panel ("FRUITY" red italic, "DX10", "FM SYNTH") and the
"Current key & range" keyboard (532 x 99). Colours from the form and FL's
thumbnail: background #303E45, psSober panels #5D6973 with a darker title tab
(#54606A), dark knobs (300 degrees) with a white pointer and a dotted ring, the
three REL knobs lighter (as in FL's thumbnail), envelope displays on a dark grid
(#38444F) with red lines and orange points. The displays draw FL's sketch (from
the paint code at 0x5b7c0): amplitude = rise over Attack, fall to the Decay
wheel's level over Decay, release to zero, each time wheel a third of the width;
modulators = Init level, to the Sustain level over TIME, release, each a half;
their points can be dragged. The keyboard shows the channel's root key (blue),
its key range (ruler, keys outside dimmed), C keys shaded and the playing keys;
left-click plays (vertical position = velocity), right-click sets the root key,
dragging on the ruler sets the range, the mouse wheel scrolls by an octave (the
view starts two octaves below the root, C5 centred like FL). The plugin menu's
"Show keyboard" (FL: Show/Hide Keyboard) hides it and shrinks the panel to
536 x 238. Original drawing, no FL assets.
